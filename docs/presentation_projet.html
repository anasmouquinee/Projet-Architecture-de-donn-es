01. Introduction

Contexte du Projet

L'information numérique est produite en masse, nécessitant des pipelines robustes pour être exploitée de manière fiable.

La Problématique

Comment collecter, stocker et analyser des flux constants d'articles provenant de multiples sources hétérogènes (Hespress, BBC, Al Jazeera, CNN, Reuters) sans perte de données et avec une haute disponibilité ?

01. Introduction

Objectifs du Pipeline

Scraping Automatisé

Extracteurs OOP en Python avec BeautifulSoup pour divers formats de sites d'actualité.

Data Lakehouse

Architecture "Medallion" (Bronze, Silver, Gold) hébergée sur MinIO (S3-compatible).

Message Brokering

Apache Kafka & Zookeeper pour découpler l'ingestion et gérer de hauts débits.

Data Visualization

Apache Superset connecté au Data Warehouse PostgreSQL pour la BI.

02. Conception Technique

Architecture Système (4 Couches)

Couche Présentation & BI

Apache Superset

Tableaux de bord dynamiques, Analyse des tendances d'actualité

Couche Data Warehouse

PostgreSQL

Données "Gold" structurées (Articles raffinés, agrégations)

Couche Data Lake & Streaming

MinIO (Object Storage) + Apache Kafka (Message Broker)

Buckets: Bronze (Brut), Silver (Nettoyé), Qualité, Quarantaine

Couche Ingestion & Orchestration

Apache Airflow + Python Scrapers (BeautifulSoup)

Exécution de DAGs planifiés, extraction de sites d'informations

05. Robustesse

Fiabilité & Gouvernance

Qualité des Données

  • Dossiers dédiés dans MinIO: quality/ et quarantine/.
  • Les articles corrompus ou invalides sont automatiquement écartés sans stopper le pipeline.
  • Système de Lineage Tracking pour tracer la provenance de la donnée.

Tolérance aux Pannes

  • Apache Kafka permet de stocker les articles en cas d'indisponibilité de la base.
  • Airflow gère les "retries" automatiques sur échec des scrapers.
  • Infrastructure Docker-Compose avec redémarrage automatique (`restart: unless-stopped`).
